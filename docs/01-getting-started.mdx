## Installation

Michi is a monorepo package. Clone the repo and install dependencies:

```bash
git clone https://github.com/atharvdange618/Michi.git
cd Michi
pnpm install
```

The router package lives at `packages/michi`. The demo app lives at `apps/demo`.

## Project Structure

Create a `routes/` folder for your route files. The folder structure determines the route tree:

```text
src/
  routes/
    __root.tsx          - Root layout (wraps everything)
    index.tsx           - Home page (/)
    about.tsx           - About page (/about)
    user/
      $id.tsx           - Dynamic route (/user/:id)
    settings.tsx        - Layout for /settings/*
    settings/
      profile.tsx       - /settings/profile
      billing.tsx       - /settings/billing
  main.tsx              - Entry point
```

### Filename Rules

| Filename      | Meaning                                                |
| ------------- | ------------------------------------------------------ |
| `__root.tsx`  | Root layout, wraps everything                          |
| `_prefix.tsx` | Pathless layout, no URL segment contributed            |
| `index.tsx`   | Takes its parent's path, no segment appended           |
| `$.tsx`       | Wildcard `*`                                           |
| `$id.tsx`     | Dynamic param segment                                  |
| anything else | Static segment                                         |

A file paired with a same-named directory acts as a layout for that directory's contents. For example, `settings.tsx` + `settings/` means `settings.tsx` wraps `settings/profile.tsx` and `settings/billing.tsx`.

## Generate the Route Tree

Run the codegen command to read your `routes/` folder and generate the route tree:

```bash
pnpm codegen
```

This produces `src/routeTree.gen.ts` -- a file with real imports and a nested object literal. It detects which exports each route file provides (`loader`, `validateSearch`, `errorComponent`) by parsing the AST, without executing any code.

**Do not edit `routeTree.gen.ts` by hand.** It gets overwritten every time you run `pnpm codegen`.

## Set Up the Router

Import the generated tree and pass it to `Router`:

```tsx main.tsx
import { Router, RouterProvider } from "michi";
import { routeTree } from "./routeTree.gen";

const router = new Router(routeTree);

function App() {
  return <RouterProvider router={router} />;
}
```

That's it. No manual route definitions, no imports to wire up. The folder structure is the source of truth.

## Writing a Route Component

A route component is a regular React component. Use `useParams` to read dynamic segments:

```tsx routes/user/$id.tsx
import { useParams } from "michi";

export default function UserPage() {
  const { id } = useParams<{ id: string }>();
  return <h1>Hello, {id}</h1>;
}
```

## Adding a Loader

Loaders fetch data before the component renders. Export a `loader` function from the route file. The codegen picks it up automatically -- no manual wiring needed:

```tsx routes/user/$id.tsx
import { useParams, useLoaderData } from "michi";
import type { LoaderContext } from "michi";

export async function loader({ params }: LoaderContext<{ id: string }>) {
  const res = await fetch(`/api/user/${params.id}`);
  return res.json();
}

export default function UserPage() {
  const user = useLoaderData<{ name: string; email: string }>();
  return (
    <div>
      <h1>{user.name}</h1>
      <p>{user.email}</p>
    </div>
  );
}
```

Run `pnpm codegen` again after adding a new export, and the generated tree updates to include it.

## Programmatic Navigation

Use the `useRouter` hook to navigate from event handlers or effects:

```tsx react.tsx
import { useRouter } from "michi";

function LogoutButton() {
  const router = useRouter();

  return <button onClick={() => router.navigate("/")}>Log out</button>;
}
```

## Link Component

Use `Link` for client-side navigation. It renders an `<a>` tag with `href` for accessibility:

```tsx react.tsx
import { Link } from "michi";

<Link to="/about">About</Link>;
```

## Error Handling

Each route can define a custom error component. Export `errorComponent` from the route file and the codegen picks it up:

```tsx routes/user/$id.tsx
export function errorComponent({ error }: { error: unknown }) {
  return <div>Something went wrong: {String(error)}</div>;
}
```

Errors thrown in loaders are caught and rendered by the route's error boundary without crashing the rest of the app.
